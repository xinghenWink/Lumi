# 版本策略

Lumi 使用 `v主版本.次版本.修订版本` 标签发布。产品版本与 M0～M7 开发里程碑独立：里程碑完成表示约定的初期范围已验收，不代表产品必须进入 1.0。

| 版本     | 定位                                                                   |
| -------- | ---------------------------------------------------------------------- |
| `v0.0.1` | 初始版本：工程脚手架、部署和 CI 基础。                                 |
| `v0.1.0` | 首个可运行的基础版本：账号、聊天、生图、积分、后台及部署运维链路可用。 |
| `v0.1.x` | 当前基础版本的问题修复与小幅兼容改进。                                 |
| `v0.2.0` | 完整 React 前端重构：对话式工作区与独立管理后台，保留既有 API 和数据。 |
| 后续 0.x | 按实际需求逐步增加功能或调整体验；具体范围随对应版本确定。             |
| `v1.0.0` | 在实际使用与迭代后，产品和接口达到约定的成熟程度时再发布。             |

0.x 阶段允许演进；涉及接口、配置或数据兼容性变化时，在发行说明中写清影响和升级办法。数据库迁移仍遵守 forward-only，版本小于 1.0 不降低备份、数据完整性和验收要求。

## 当前版本的编号调整

2026-10-23，用户将当前可用版本定位为 `v0.1.0`，公开发行序列调整为 `v0.0.1 → v0.1.0`。此前误用 `v1.0.0` 编号的发行记录转为草稿，并使用 `archive/early-v1.0.0-20261023` 归档标签保留同一个原始 annotated tag 对象、提交、附件和镜像身份。核对归档完整后撤下误用的 `v1.0.0` 标签，留给未来成熟版本使用；不修改原提交或其验收证据。

`v0.1.0` 使用相同的业务代码重新走 CI、双架构构建、原生启动验证和正式镜像部署验收。二进制 `/api/version`、镜像标签、官方归档身份 JSON、部署默认值与 GitHub Release 均使用 `v0.1.0`。没有新增功能、依赖、API 或数据库迁移。

## 发布与升级

- 2026-10-24，用户在 React 迁移验收后授权合并并发布 `v0.2.0`。该版本沿用后端、OpenAPI、SSE、任务与账务规则，无新增 SQL 迁移；[发布计划](RELEASE_V0.2.0.md) 与实际 Release 记录最终构建和验收结果。
- 应用版本由 Git tag 注入构建；`main` 的自动镜像仍标记为 `edge`，不代表新的正式版本。
- 完整检查通过后发布版本；优先固定版本标签或 digest 部署，升级前备份数据库、图片与密钥。
- 当前编号调整不会重新初始化账号或数据。已部署旧编号的实例使用同一数据目录和密钥切换到官方 `v0.1.0` 镜像。
- 本次用户授权的误编号归档是一次性更正；后续发布增加新标签，不移动已发布版本。流程见 [部署手册](DEPLOYMENT.md#正式发布门槛)。
