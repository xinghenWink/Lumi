# 上游实例契约

## 渠道显示名称与批量管理

- 在「上游渠道」填写「渠道显示名称」后，用户端模型名显示为 `模型名称（渠道显示名称）`。升级后已有渠道的显示名称默认为空。一个模型可用多个渠道时，按路由优先级和渠道优先级选择名称，数值越小越优先。优先渠道留空时使用原模型名。已有手动后缀如需调整，可在平台模型编辑器中修改基础模型名。
- 在「平台模型」选择「按渠道管理」，可查看绑定该渠道的模型。批量启用、停用、删除始终覆盖该渠道的全部绑定，包括当前页和筛选范围以外的绑定。只绑定该渠道的模型按整条模型处理，共享模型只处理该渠道的路由。
- 停用独占模型会清除默认标记。删除独占模型也会删除其专属价格。共享模型的状态、专属价格与其他渠道路由继续保留。批量操作记录在审计日志中，图片任务保留提交时的模型名称快照。

## 生图质量

- 在模型管理的「可用质量」中，可为支持的 2.5 / 2.6 Sunburst、Flare 等生图模型勾选「超高（xhigh）」和「最高（max）」。启用前确认该模型的每条启用路由支持所选值。
- 「价格与赠送」为五种质量分别提供生图、改图的全局默认价格。升级时用对应操作的 high 价格初始化 xhigh 和 max，后台可按需调整。启用的模型专属价优先，专属规则缺失或停用时使用全局价。
- 从已启用的生图模型列表选择模型即可添加专属规则。工作台和画布显示已勾选且当前操作有可用价格的档位，Lumi 将选中的 `quality` 原样传给上游。

## 生图规划强度

- 在模型管理中为 GPT Image 2.6 Sunburst、Flare 或其代理别名勾选「已验证所有启用路由支持规划强度」。先确认每条启用路由的生图及已配置的改图接口接受对应字段，路由变更后重新核对。已有模型和新导入模型默认关闭。
- 工作台、画布和全屏 AI 改图提供「官方默认 / 低 / 中 / 高」。显式档位以 `complexity=low|medium|high` 发送。选择官方默认时，Lumi 省略该字段，由上游模型决定默认值。OpenAI 的 2.6 Sunburst 和 Flare 当前默认使用 `high`。 [OpenAI 生图指南](https://developers.openai.com/api/docs/guides/image-generation#set-image-complexity)
- 规划强度独立于画质和 Lumi 积分计价。图片任务和画布运行 API 接受可选的 `complexity`，可见的任务详情会返回显式选择。

## 自动比例

- 工作台和画布选择「自动」时，Lumi 按 `size=auto` 报价，并把同一尺寸值传给生图或参考图改图接口。上游决定输出尺寸，任务按实际图片像素记录结果。
- 生图设置默认启用「自动」。继承站点预设的模型跟随该开关。显式配置尺寸的模型需要同时在平台模型的尺寸列表和生图设置的自定义尺寸列表中添加 `auto`。按实际部署的上游路由确认支持情况。
- 未保存个人偏好的账号默认使用「自动」。已有偏好和画布节点继续使用已保存且可用的比例。

## GIF 动图

- 安装含迁移 `00021` 的版本后，在模型的每条启用路由上确认 `/v1/images/generations` 和已配置的 `/v1/images/edits` 支持 `output_format=gif`，再在模型管理勾选「已验证所有启用路由支持 GIF 输出」。已有模型默认关闭。
- 工作台提供「自动 / PNG 静态图 / GIF 动图」。自动模式识别「生成 GIF 动图」和 `create a GIF of …` 等明确的输出指令。使用 API 时可以传 `output_format`，可选值为 `png`、`gif`，省略即使用自动模式。
- GIF 请求保留所选尺寸、质量和数量。支持的尺寸和总像素预算由渠道决定。Lumi 使用 GPT Image 默认的 Base64 响应，还可接收同源结果 URL、GIF Base64 data URL 和单结果 `image/gif` 响应。[OpenAI GIF 接口文档](https://developers.openai.com/api/docs/guides/image-generation#generate-animated-gif-output)
- 原图和 ZIP 保留动画，预览播放原图。缩略图使用首帧 WebP，复制和再次作为改图参考使用首帧 PNG。GIF 原图沿用 20 MiB 和单图 2400 万像素的上限，最多 512 帧和累计 9600 万帧像素。

## 全屏编辑器

- 标注、定位评论和擦除沿用普通单参考图改图。Lumi 发送一张带标记的引导图和文字指令。模型据此重绘，结果可能影响选区周围。
- 去背启用前，运营者在实际部署的模型每一条启用路由上验证 `/v1/images/edits` 接受 `background=transparent` 和 `output_format=png`，并返回含透明像素和可见主体的 PNG。验证通过后，在模型配置勾选「已验证所有启用路由支持透明背景改图」。渠道或路由发生变化时重新验证。下方已有实例探测未覆盖这些透明输出字段。
- 调整大小复用模型尺寸配置和当前生图站点预设。输出按实际像素校验选择的比例，允许一像素取整差异。去背或比例校验失败时，通过原有任务结算退回积分。
