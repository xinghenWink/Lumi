# Lumi 开发分析与里程碑计划

M0 与 M1 的功能验收已通过，用户已授权按 M0 → M1 的顺序合并到 main。M0 已发布 `v0.0.1` 并通过 amd64 / arm64 发布镜像的真实 Compose 运行验证；M1 详细范围与结果见 [M1_PLAN.md](M1_PLAN.md) 和 [M1_ACCEPTANCE.md](M1_ACCEPTANCE.md)。后续业务从 M2 继续，本轮不扩展阶段范围。

## 基线与约束

- 需求基线：`REQUIREMENTS.md` v1.0；交互基线：`Lumi-原型.html` 与 `Lumi-原型对接文档.md` v2.2。
- 开发前仓库仅有文档与原型，没有可复用的业务代码。HTML 作为验收参考，正式代码重新实现。
- 技术栈保持 Go / Gin / PostgreSQL 16 / Redis 7 / pgx / sqlc / goose 与 Vue 3 / TypeScript / Vite / Pinia / Vue Router / TailwindCSS。
- 每次只推进一个里程碑，通过验证后再进入下一个。分支使用 `codex/` 前缀；提交使用 Conventional Commits。
- 使用根目录 `AGENTS.md` 的项目专用约定：代码、代码注释英文；用户文案通过 i18n 提供，默认 zh-CN。

## 需求与原型差异处理

| 项目                 | 开发决策                                                                                   |
| -------------------- | ------------------------------------------------------------------------------------------ |
| 模型选择器位置       | 采用更新的原型交接说明：输入框底部、发送按钮左侧，弹层向上展开；不采用需求早期的顶部位置。 |
| 角色切换、模拟认证   | 不进入正式代码。M1 实现后端认证、RBAC 与用户隔离。                                         |
| 模拟聊天、SVG 生图   | 不进入正式代码。M3 实测上游契约，M4/M5 接入真实能力。                                      |
| 积分、兑换、退款     | 服务端事务与幂等实现，禁止复用原型的 localStorage 记账。每日桶跨日后的退款退入永久桶。     |
| 注册赠送跨里程碑     | M1 建立账号事务边界，M2 接入积分。M1 阶段不宣称注册赠送已完成。                            |
| 路由、会话状态       | M4/M5 分离聊天与生图历史，分别保留草稿、会话与模型；移动端从 320px 验收。                  |
| 管理员与上游密钥     | 管理权限后端判断；上游密钥加密入库，不返回明文、不进入日志。                               |
| 原型交接中的旧文件名 | 以仓库实际存在的上述文件为准，不创建重复设计稿。                                           |

## 本轮 M0 文件与状态清单

- `backend/cmd/lumi`：serve / migrate / healthcheck，信号退出与构建信息。
- `backend/internal/config`、`platform/{db,redis,logger}`、`http/{handler,middleware,router}`：配置校验、连接、就绪检查、安全头、请求日志与统一错误。
- `backend/migrations`、`queries`、`sqlc.yaml`：嵌入的 forward-only 基础迁移、带 advisory lock 的 goose Provider、sqlc 查询。
- `backend/web`：嵌入 Vite 产物，SPA 路由回退；未构建时返回明确的构建提示。
- `frontend`：Vue + strict TypeScript、i18n、Pinia、懒加载路由与基础欢迎页。状态包含版本加载、成功、失败重试、404；M0 不开放业务入口。
- `docs/openapi.yaml`：仅声明本阶段实际存在的 `/healthz`、`/readyz`、`/api/version`；前端生成类型。
- `Dockerfile`、`deploy`、`Makefile`、`.github/workflows`：开发依赖、完整本地构建、非 root 镜像、质量检查、多架构发布。
- 后端单元测试与 PG/Redis 集成测试；前端 Vitest 与 Playwright 基础冒烟。实际执行结果另见 `M0_ACCEPTANCE.md`。

## 本轮边界

M0 只提供公开的工程欢迎页，不模拟登录、聊天、生图、积分或后台。数据库只建立基础设施 schema，不提前建立 M1/M2 业务表。尚无上游实例凭据，M3 的契约探测保持待办。
