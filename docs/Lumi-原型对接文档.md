# Lumi 原型优化说明与 Codex 交接建议

版本：UI prototype v2.2（2026-10-21，修复用户菜单尺寸，移动模型选择至输入框）  
基准：用户提供的《AI 对话 + 生图 C 端平台 · 需求清单（Codex 执行版）》v1.0、`Lumi · 对话与生图 (2).html`。

## 1. 本次优化范围

原型为**独立单文件 HTML**，可直接用现代浏览器打开，**不依赖 CDN 或第三方服务**。保留原需求的「聊天／生图」双模式和对话式生图路径，同时做以下优化：

| 区域 | 本版可演示交互 | 对应需求 |
| --- | --- | --- |
| 统一创作空间 | 模式切换、独立会话列表、新建/置顶/重命名/删除、输入框内模型切换、空状态、深浅色 | F-CHAT-01、04；F-IMG-01 |
| 聊天 | 逐字模拟流式回答、停止、复制、编辑重发、重新生成提示词 | F-CHAT-02、05（**模拟结果**） |
| 生图 | 质量/比例/张数、费用预估、积分不足拦截、模拟任务占位和结果、图片预览/下载 | F-IMG-02～08（**模拟结果**） |
| 改图 | 本地图片选择、历史图库选图、结果图加入编辑、参考图删除 | F-IMG-11～14（**未实际上传/编辑**） |
| 个人中心 | 双桶积分、兑换码、流水、作品图库、画质筛选、会话管理、用户资料和偏好 | F-ME-01～07（**本地演示**） |
| 管理后台 | 独立侧栏与页面：概览、用户、新增/编辑/禁用/调积分、价格、赠送、批量生成兑换码、导出 CSV、任务、审计、设置 | F-ADM 相关的 UI 骨架及部分**本地模拟操作** |
| 适配 | 桌面/手机响应式、侧栏抽屉、基础焦点样式、减少动效偏好 | NFR 兼容性与体验部分 |
| 演示身份切换 | 普通用户与超级管理员一键切换，保存各自会话、作品、积分与个人资料；平台配置与用户列表共享，禁止普通用户打开管理后台 | **仅用于产品验收的模拟功能，不属于线上需求** |

## 2. 交互说明

1. 双击 `Lumi_交互优化原型_v2.html`，进入已填充演示数据的工作空间。
2. 顶部切换「聊天／生图」，侧边会话列表会随模式变化；**模型选择位于输入框右下角、发送按钮左侧**，下拉选项向上展开；两种模式各自保留选定模型。
3. 生图模式点击输入框下方参数按钮，调整质量、比例和数量；点击「+」上传或从图库选择参考图。
4. 输入提示词后发送，约 2 秒后出现**程序生成的 SVG 演示图片**；可预览、下载和加入编辑。
5. 个人中心 → 积分与流水：可使用示例兑换码 `LUMI-DEMO-2026` 领取 50 演示积分（限兑一次）。
6. 左下角用户头像 → 侧栏范围内的弹出菜单 → 管理后台：可体验用户管理、调整积分、价格/赠送配置、兑换码批量生成和导出。
7. **左侧栏「演示身份」** 可以一键切换「普通用户／超级管理员」；用户头像弹出菜单、后台左侧栏、个人中心偏好与安全页也有入口。普通用户点击管理员后直接进入后台，管理员切为用户后返回个人工作区。两种身份的会话、积分、图片分别保存；新增演示用户后可以返回管理员，不必恢复初始数据。
8. 深浅色切换、会话、余额等可在支持 localStorage 的浏览器中保存；原有 v2 演示数据可迁移至此版；在个人中心可恢复初始演示数据。
9. `Ctrl/Cmd + K` 搜索会话；输入框 `Enter` 发送、`Shift+Enter` 换行。

## 3. 明确的原型边界（Codex 不能视为完成）

- **模拟登录／注册不是身份认证**，密码不校验、不入库；前端角色判断不能替代管理员后端权限检查。
- **一键切换普通用户／超级管理员仅用于 HTML 原型验收。** 不得在正式站点提供提升到管理员身份的开关。生产环境必须由可信后端验证会话、角色与每条管理 API 的权限，并实现真实用户数据隔离；不可依赖 localStorage 或 HTML 按钮阻止访问。
- **模拟聊天不是 SSE**；回复由固定规则产生，没有调用 chatgpt2api、没有真实 Markdown 流式解析或 token 统计。
- **模拟生图不是图像模型输出**。每张示例图用本地 SVG 绘制；上传的参考图片暂存当前页面，不上传服务器。尺寸选择和真实接口契约尚未核验。
- **积分流水、扣费、退款与兑换码是 JavaScript 本地状态操作**，不具有事务一致性、服务端幂等或并发安全性。演示刷新取消模拟任务的退款也不是生产恢复策略。
- **模型/上游**只是平台名称和静态状态展示，不保存上游密钥，未实现测试连接、模型同步、渠道绑定或熔断。
- **审计日志**只是当前浏览器操作日志，并非不可篡改或可信的后端审计记录。
- 单文件内联 CSS/JS 仅为交互验证。生产环境应按原需求采用 Vue 3、TypeScript、组件化、API 类型生成、CSP、Go 后端、PostgreSQL、Redis，不应把演示 JS 直接复制到线上。

## 4. 建议交给 Codex 的 UI 实现原则

在 `docs/REQUIREMENTS.md` 正文规则不变的前提下，把此 HTML 作为**交互与布局验收参考**（不是可移植代码）。按原规划 M0～M7 开发，UI 重点要求：

1. `AppShell` 统管模式、会话导航、用户菜单；**模型选择器放在 `ChatComposer` / `ImageComposer` 底部工具栏靠右、发送按钮左边**，不要放回顶部导航。模型弹层向上展开、右对齐且不超出窄屏。左下角用户头像的菜单仅限侧栏宽度，定位锚点使用侧栏底部容器，不能铺满主工作区。两个 Composer 共用基本布局，但参数、引用状态和实际提交逻辑独立。
2. 生图会话必须完整呈现 `queued/running/succeeded/partial/failed/canceled`，图片逐张显示成功或失败；生图结果可直接作为新任务的输入参考图。
3. 积分费用预估来自**服务端可见价格规则**，提交时由后端最终计算并校验，客户端数字只是提示；失败时由后端按原扣费桶结算退款。
4. 每种模式各自保留最后打开的会话、输入草稿和模型，不得因模式切换重建页面或丢失用户内容；图片数据使用鉴权与缩略图方案。
5. 后台必须做独立布局和 RBAC；此原型的「演示身份切换」不得复制到正式版。用户详情、兑换码、模型路由、审核任务、审计日志为独立模块，不能停留在仅弹 Toast 的占位交互。
6. 将提示词、生成结果、引用图、质量、实际尺寸、模型 ID、任务状态和积分快照建立稳定数据结构。手机宽度从 320px 起进行实际验收，包括模型下拉、侧栏账户菜单及生图参数的边界。
7. 正式上线前逐条完成原需求中的 F、BR、NFR 条款。特别注意：`UPSTREAM_CONTRACT.md` 必须根据你自己的 chatgpt2api 实例**实测**生成，再决定图像 `quality/size/n/images` 字段。

## 5. 可直接给 Codex 的增量指令

> 请先阅读 `docs/REQUIREMENTS.md` 和 `AGENTS.md`，然后参考 `docs/Lumi_原型优化说明与Codex交接.md` 以及 `design/Lumi_交互优化原型.html`。HTML 是交互与视觉设计稿，包含大量本地模拟逻辑，不能当成生产实现。严格按当前里程碑及技术栈推进。将布局拆为 Vue 组件，所有真实数据只来自后端 API；重要的生图扣费、任务状态、退款、兑换与管理员授权必须后端实现和测试。先对照原型列出本里程碑需实现的页面与状态清单，然后编码、测试、报告差异。不复制参考开源项目代码。

## 6. 进一步需要确认的视觉偏好

本版采用浅色简洁 + 靛紫强调色、聊天/生图同一主工作区、后台独立左侧导航。可以继续依据实际偏好微调：字体和配色、图片操作按钮密度、积分展示位置、顶部模式切换样式、移动端优先级。
