- ADR-107：复核发现后续诊断脚本的 PG / Redis 经过宿主端口映射，而目标服务器此前通过的正式容量脚本采用直接回环监听。统一最终容量拓扑：独立空 PG / Redis 容器以 host 网络仅监听 127.0.0.1:15432 / 16379，匹配正式 Compose 容器之间无需宿主端口转发的依赖直连路径；不改变 PostgreSQL 持久性设置、应用两核配置、100 VU / 60 秒、全部首轮样本或原始阈值。CI 使用随机临时凭据、显式就绪检查及 always 清理；功能 E2E 继续覆盖原 Compose 网络服务。无新增依赖，未将调整传输路径当成应用查询修复。

- ADR-105：tag 后文档 CI 的首轮浏览器 SSE p95 221ms，完整重跑时浏览器通过但混合负载 p95 292.30ms，说明容量结果仍存在环境或阶段性波动，不能据旧通过轮次宣称最新 CI 全绿。补充容量前后可用 CPU、内存、cgroup 配额 / 节流及 CPU / IO 压力快照，启用已有超时流的前置 / 上游 / 后置耗时诊断；浏览器报告在断言前落盘，保证失败证据保留。仅使用 Node 标准库，全部样本及原阈值不变；发布保持草稿直到最终 CI 通过，不改变官方镜像或标签。

- ADR-104：官方归档在 Docker 29.1.3 / containerd 导入后的 inspect ID 为归档 manifest digest，而原生 CI 传统存储记录的是配置 digest。保持正式 v1.0.0 镜像、标签和官方 JSON 不变；用配置 SHA256、每层内容 SHA256、归档 manifest 引用、本机 RootFS / 运行配置建立完整身份链，再实际核对服务版本和 commit。补充离线核验文档；可选工具仅用目标 Ubuntu 已有 Python 3.12 标准库，不加应用或 pip 依赖。此为 tag 后的文档澄清，不改变已验证镜像内容。

- ADR-103：本地与目标服务器通过的容量场景均显式使用 `GOMAXPROCS=2`；CI 原来依赖 runner 的默认值，连同 Redis 默认池容量随宿主 CPU 数变化。CI 负载步骤固定相同的 2 个 Go 执行核，并在环境报告记录该值，匹配两核应用容量目标。100 VU / 60 秒、首轮、读 / 流延迟阈值及业务断言均不变，不增加 runner 资源。

- ADR-102：用户要求所有 DoD / CI 完成后才正式发布。tag 工作流在质量、Compose 演练及原生双架构 digest 验收后，创建带完整附件的 Release 草稿；授权发布者再把官方归档导入目标服务器验收，确认整个工作流全绿后发布草稿。服务器 SSH 凭据不上传 Actions；无需将广泛仓库凭据交给目标服务器。此步骤使用既有 gh CLI，无新增运行依赖。

- ADR-101：仅缩小共享池仍有首轮排队；按资源用途分为 8 个普通连接和 4 个交互连接，总上限 12。鉴权与聊天使用交互池，聊天路由读取也使用该池的 Queries；生图、账务和后台工作使用普通池。两池在迁移后准备、分别关闭，readiness 同时检查两者。真实 PG 回归占满普通池且仅保留一个交互连接，鉴权及带图片引用的聊天仍须在 5 秒内接受。目标 Ubuntu 原始 100 VU / 60 秒连续通过，正式实现复测平台 p95 88.08ms、读取 p95 16.67ms；未采用实验中的强制 generic plan、EXPLAIN 或 Redis 预热。压测与编译 / 镜像构建串行，避免把构建资源争用混入容量验收；重叠构建的失败轮次仍保留为诊断记录。

- ADR-100：Go 执行跟踪显示混合负载首轮的共享数据库池排队明显。普通短 GET 在鉴权前按实例限 2 个并发，等待可随请求取消；聊天发送 / 停止等写请求、SSE、文件传输和导出不占此名额，避免长响应阻塞普通读取。鉴权、游标、返回数据与压测样本不变；补充满槽下交互仍可执行及取消等待不进入处理器的回归。无新增 API、迁移或依赖。

- ADR-099：当前工作站的仓库凭据无 GHCR 读取权限，正式工作流在原生 amd64 镜像按 digest 验收后导出同一镜像为私有 Release 附件，附 image ID / manifest digest / commit。服务器可导入已验证归档，不传递工作站广泛仓库凭据，也不另行编译冒充正式镜像；GHCR 保留双架构和最小权限 PAT 标准路径。仅复用已锁定的 artifact action，无运行依赖变化。

- ADR-097：聊天两秒检查点与最终保存合并为单条原子 CTE：先锁会话租约，更新仍在 streaming 的消息，仅在保存成功后续租或释放。取消、删除、租约丢失及已恢复消息维持原错误语义，不关闭 WAL 同步、不改变两秒保存周期。
- ADR-098：CI 实测 Azure HTTP APT 镜像下载 25.9 MB 用时 9 分 39 秒，改用 Ubuntu 官方 HTTPS 主镜像；继续完整安装 Chromium 系统依赖，不跳过浏览器或性能断言。质量任务保留有界的 35 分钟预算以容纳依赖下载波动。

- ADR-096：混合负载下生图提交的长事务占满共享池，使用每实例 2 个可取消的提交准备槽，为鉴权与聊天保留连接。此限制仅覆盖提交 / 扣费 / 创建任务阶段，不替代后台配置的全站与每用户生成并发；已接收任务仍按原队列执行。补充等待取消不触碰数据库 / 扣费依赖的回归，保持 100 VU、20 SSE、5 生图提交用户及原延迟阈值。

- ADR-093：余额读取与聊天设置采用实例内 30 秒缓存，配置写入提交后主动失效；扣费 / 退款仍在事务内读取实时配置。增加每日赠送 0→5 的立即失效回归，聊天配置返回时复制标题模型指针，避免调用方修改缓存。
- ADR-094：对缩小连接池后的事务路径继续审计，视觉引用的所有权查询及标题模型验证也复用当前事务连接；视觉续传回归预占全部备用连接，仍须在 5 秒内接受请求。续传去除循环前重复的会话读取，首次循环仍执行鉴权及所有权校验。
- ADR-095：模型 / 路由读取及成功调用的熔断重置 / 历史记录分别使用 pgx Batch，复用 sqlc 常量及扫描器，减少同步往返；调用记账保持同步完成，成功更新与历史写入同批提交。原始 100 VU 场景、首轮采样和 <100ms 阈值保持不变，不用丢弃冷启动样本或稀释统计来通过验收。

- ADR-090：生图事务内的模型 / 路由查询复用传入 sqlc Queries，禁止再次获取池连接；用预占所有备用连接的真实 PG 测试复现原死锁并验证修复。经过 4 / 8 / 16 / 20 连接对照，单池 16 配合提交准备槽及批处理曾在本地达到 p95 60.25ms、最大 78.13ms；后续 Linux 首轮排队改由 ADR-101 的 8+4 隔离池解决。启动前准备连接、错开连接寿命；迁移后重新建立带热点 SQL 描述的池，AfterConnect 同样覆盖替换连接。仅 Prepare，不执行业务 SQL，不新增运行依赖。
- ADR-091：聊天前置读取及配额 / 助手 / 会话占用写入使用 pgx Batch 合并往返，复用生成的 SQL 常量和扫描器，保持用户 → 会话的锁顺序。读取历史后仍须先完成身份和所有权校验才可使用；配额拒绝时整个外层事务回滚，包括已排入批次的写入。
- ADR-092：积分余额读取把懒重置、过期流水及赠送流水合并为一条原子 CTE，配置验证在调用前执行；用户锁、账户锁、每日幂等键和版本递增语义保持一致。补充“赠送流水插入失败时账户、过期流水全部回滚”测试，并保留跨日并发和退款回归。无 schema / OpenAPI 路径变化。

- ADR-088：并发调用成功时，仅在上游存在故障计数 / 熔断 / 探测 / 错误状态时执行重置 UPDATE，避免所有健康流争抢同一渠道行锁和无效 WAL。保持失败和半开成功恢复语义；新增持有健康渠道写锁时成功记录仍可立即返回的 PG 回归。M7 实际探测覆盖三档 quality、n=1～4、横 / 竖 / auto 及 multipart 改图；探测报告新增实际图片尺寸，不以请求值冒充结果。
- ADR-089：用户提供测试服务器及上游凭据并明确授权全部 DoD / CI 后发布。服务器验收使用独立目录、独立 Compose 项目及仅回环绑定的数据库 / 缓存，保留既有 8787 服务。先导入本机受信构建镜像完成 M6↔M7 升级恢复演练，发布后再验证 GHCR 正式镜像。服务器来源以实际机器为证，不将自签测试 TLS 证书描述为公网可信证书。

- ADR-087：100 VU 压测发现 Redis 的阻塞 XREAD 可耗尽共用连接池，拖延 XADD、鉴权与限流。为聊天续传设独立 32 连接读取池，与普通命令池分别关闭；保留 200ms 阻塞超时与原续传语义。增加单命令连接 / 20 个阻塞读者的真实 Redis 回归，并在 2 个 Go 执行核下重新压测，不降低延迟阈值。

- ADR-080：M7 基于 M6 `e9f87b2`，独立 `codex/m7-release` 分支 / PR；不新增业务模块、SQL 迁移或 API 路径，不自动合并前序 PR。真实上游和干净目标服务器未验收前不发布 v1.0.0；本地或 CI 空目录 Compose 不冒充远程上线验收。
- ADR-081：生产 HTTP / 非 Secure Cookie 仅允许回环地址，公开地址必须 HTTPS + Secure；新增配置与 Cookie 属性回归。内嵌标准库 time/tzdata，保证 trimpath 独立二进制不依赖宿主 Go 安装；无新增运行库。
- ADR-082：负载固定 k6 1.3.0（独立测试工具），100 个不同身份、75 读 / 20 SSE / 5 图片用户运行 60 秒。仅 integration + test + 显式回环专用数据库可生成 fixture；令牌文件 0600 且忽略，不上传 CI。上游使用本地确定性 SSE / 有效 PNG；平台耗时扣除实际 fixture 时段，标题 fixture 即时返回，不混入额外供应商耗时。保留失败报告，不放宽 <100ms、完整流和成功图阈值。
- ADR-083：安全备份以单实例内置 PG / Redis Compose 为边界；停止 app 后 pg_dump + 图片 + 密钥共同归档，校验、原子发布后轮换。自动恢复仅空目录、可信备份，拒绝路径穿越和链接；不覆盖任何已有部署。外部数据库 URL 拒绝自动备份 / 恢复，多实例需运营者协调全部写入。
- ADR-084：桌面 / 移动 E2E 保留既有回归，补齐同用户注册、聊天、兑换、生图、后台调账链路；500 消息、1000 图 fixture 只增加隔离测试数据和真实文件字节，不调用真实付费生成。Lighthouse 和交互采样注明环境，不将实验室上界当作现场 INP。
- ADR-085：quic-go 间接依赖锁定升级 0.59.0 → 0.59.1，修复 [GO-2026-5676](https://pkg.go.dev/vuln/GO-2026-5676)。新增锁定的扫描工具 govulncheck 1.9.0，仅 CI / 本地测试使用，不加入运行依赖。发布继续使用 Go 1.26.10，修复 [GO-2026-6809](https://pkg.go.dev/vuln/GO-2026-6809) 等标准库问题；宿主较新的未打补丁版本不能替代。
- ADR-086：安装脚本仅生成首次缺失配置，密码只留 0600 文件；部署包随版本 Release 分发。Caddy / Nginx 例子关闭流缓冲并覆盖客户端转发头；TRUSTED_PROXIES 需按实际代理源地址填写，不默认信任整个 Docker / 私网网段。备份含秘密，必须受限保存并由运营者加密后异地转存。

## M6（2026-10-23）

- ADR-079：聊天 vision 使用所有者图片的规范化缩略图再缩放为长边 ≤256px PNG，避免把四张 10 MB 原图编码为超大 JSON；总上下文 JSON 内容限制 3 MiB，超限在保存新消息事务内拒绝。原图与生图编辑引用保持既有行为。

- ADR-065：M6 独立分支基于 M5，新增 00008；仅实施全部 P1 与 M6 明确列出的后台补全，不执行 M7 压测、部署演练或发布。无新增项目依赖。
- ADR-066：密码重置令牌为 256 位随机值，数据库仅存哈希，有效 30 分钟、单次使用并绑定 token_version；重置与吊销全部登录在同一事务。链接令牌放 URL fragment，页面读取后移除，不进入 HTTP 请求或日志。忘记密码对不存在账号与邮件投递失败均返回统一受理结果，避免故障期间枚举账号；投递失败仅记不含个人资料的服务日志，不打印重置链接。管理员测试邮件仍明确返回 SMTP 状态。
- ADR-067：Turnstile 使用固定官方 Siteverify 地址，校验 success、hostname 与 action；secret 经 AES-GCM 入库，响应和审计只暴露 configured。CSP 仅为官方 challenges.cloudflare.com 增加 script / frame / connect 来源。参考：[官方验证说明](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/)。
- ADR-068：每 IP 注册上限默认 5，使用 Redis 滑动 24 小时窗口，0 关闭；配额保守地计入通过输入验证后尝试的注册，即便后续邮箱验证码、重复邮箱或事务失败也不返还。Redis 故障拒绝注册，避免绕过配额。沿用独立每分钟限制。
- ADR-069：个人偏好单独存表。自定义指令不复制到审计，与全局 system prompt 拼接并纳入上下文预算；vision 仅在能力明确启用时可用，只接受已有所有者文件 ID，最多 4 张，作为内联图片发送上游，历史保留引用 ID。每张保守预留 1024 估算 token；上游仍负责实际上下文限制。
- ADR-070：M6 将 HTTP 断开与停止生成分开。Redis Stream 缓冲受用户 / 会话 / request_id 隔离，TTL 5 分钟，每个事件续期；请求摘要原子去重，前端携带 Last-Event-ID 续传，刷新后可重新订阅。显式停止、账号失效或服务器退出仍取消生成；Redis 无法恢复则读取数据库检查点，崩溃后租约恢复标记 interrupted，不重新调用上游。最长执行仍为 10 分钟。
- ADR-071：同优先级路由按权重无放回随机排列，依次回退。数据库记录连续故障与熔断时限，默认 5 次 / 60 秒；过期后仅允许一个最多 10 分钟的半开探测。用户取消、内容拒绝与请求校验错误不累计故障。生图只对明确 401 / 403、429 或本地网络策略拒绝回退；超时、5xx、无效结果不重发，避免不确定写入生成重复图片。健康测试可主动检测熔断渠道。
- ADR-072：环境引导仅在渠道与平台模型均为空时生效，不覆盖已有配置。默认远程名与低风险图片参数取自已记录的 M3 实测：gpt-5-3-mini、gpt-image-2、low / 1024x1024 / n=1 / 单参考图；不同实例需要管理员修改路由。不新增付费探测请求。
- ADR-073：批量启用 / 禁用 / 删除和批量发积分每次最多 100 人，全部同事务并复用管理员保护；发积分必须提供幂等键。手动退款仅允许终态任务，退回剩余实扣金额，沿用原桶 / 跨日转永久桶，任务行锁与流水唯一键防止重复，必须备注并审计。
- ADR-074：自助删除需邮箱与当前密码，立即注销，7 天后清除个人数据；管理员删除沿用 30 天。未结算任务阻止物理清理。保留必要账务和审计记录；隐私页已说明内容查看开关与留存规则。
- ADR-075：维护任务用 Redis 60 秒租约与所有者令牌释放，执行 context 最长 45 秒；PG job_runs 限制认证清理每小时、对账每天 UTC 一次。对账单条 SQL 用同一快照比较各桶余额与流水总和，不自动改账，不一致追加审计告警。既有图片、上游调用与管理员删除清理继续使用数据库行锁和幂等恢复。
